---
title: This is data, not a script -- rebuild-tsv.sh is its only reader
description: data/generic-words/ is a bundled wordlist, split into chunk-NN.txt files (#437), rebuild-tsv.sh consults at build time to classify a vocabulary keyword as generic or specific (#232). It carries no code and is read nowhere under scripts/*-hook.sh -- the runtime hooks never consult a dictionary.
match: (^|/)data/generic-words/chunk-[0-9]+[.]txt$
---

`data/generic-words/` is a directory of plain, one-word-per-line chunk files (`chunk-00.txt`, `chunk-01.txt`, ...) `rebuild-tsv.sh` greps against, as if they were one file, when it writes the third `00-index.tsv` column (#232): a keyword found anywhere in them, verbatim, is marked `generic`; everything else, including a keyword not in them at all, is `specific`. Until #437 this was a single `data/generic-words.txt`; it was split into chunks because the Anthropic plugin directory refuses any non-image file of 256 KiB or more, and the original file was about 4x that on its own -- see `data/generic-words/README.md` for the split's own provenance note and the proof that concatenating the chunks reproduces the original byte for byte. It is consulted exactly once, at rebuild time, in the one function this repository's own contract lets read a dictionary — the hooks under `scripts/*-hook.sh` never open it, and never will, because the runtime constraint in `paths/00-manual/hooks.md` is absolute: no new dependency, and nothing resembling a dictionary lookup on the hot path.

**It lives at the repository root, a sibling of `scripts/`, and deliberately not under `scripts/data/`.** `tests/test-arg-flag-values.sh` sweeps every file `git ls-files -- scripts` returns and asks its `classify_script()` what kind of bash argument parser it is; a plain wordlist is neither bash nor a script and would land in that classifier's `not-bash-script` bucket, which the suite treats as a hard failure by design (this repository would rather fail loudly on a shape it cannot read than silently skip it) -- see `CLAUDE.md`'s note on `classify_script()` being coupled to bash specifically. Putting the file one directory higher removes it from that sweep's scope entirely, rather than adding a special case inside it.

**Bundled rather than detected, and the file's own header explains why**: a verdict that depended on which machine ran the rebuild would make two contributors produce different TSVs from identical sources, and every rebuild would show a phantom diff. Read the header before editing the list — it also records provenance: SCOWL size-35 (English, permissive) and Dicollecte/Grammalecte's Hunspell stems (French, MPL 2.0), the two sources #232's own research recommended (#251, replacing the 196-word hand-curated stand-in PR #250 shipped while a license-clean snapshot of either could not be verified inside that session's budget).

**Why this needed its own entry rather than widening `tooling.md`'s alternation.** `tooling.md` governs six *scripts* with the opposite-of-hooks contract — fail loudly, exit codes that mean something — and its own comment already explains why that list is enumerated one file at a time rather than a catch-all `scripts/` pattern (#83): a catch-all would satisfy `tests/test-dogfood-entries.sh`'s "every file under `scripts/` is matched by some rule" leg by construction, and the leg could never go red again. This file is not a script and carries none of `tooling.md`'s exit-code contract, so folding it into that alternation would have been the same mistake with a shorter path: correct on the day it landed, and silently wrong the moment `tooling.md`'s six-script table stopped being an accurate description of what the widened pattern actually covered.

Split a chunk further, add a chunk, or swap in a different verified upstream export, and this `match` still holds as long as the new content stays under `data/generic-words/` and each chunk keeps the `chunk-NN.txt` name — a genuinely different wordlist (a second list, a French-only split) needs its own entry or its own line in this `match`, for the same reason `tooling.md`'s list is enumerated rather than a glob.
