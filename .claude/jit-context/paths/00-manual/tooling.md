---
title: These six fail loudly, and their exit codes carry meaning
description: rebuild-tsv, jit-dry-run, jit-misses, jit-init, jit-doctor and jit-match are build tools, not hooks - they must fail loudly, their exit codes 0/1/2 each mean something, and the hook never-fail-hard contract does not apply.
match: (^|/)scripts/(rebuild-tsv|jit-dry-run|jit-misses|jit-init|jit-doctor|jit-match)\.sh$
---

`rebuild-tsv.sh`, `jit-dry-run.sh`, `jit-misses.sh`, `jit-init.sh`, `jit-doctor.sh` and `jit-match.sh` are build and diagnostic tools. They are run deliberately, by a person or by CI, and never inside a stranger's session.

**The alternation above is enumerated one script at a time, and that is on purpose** — `tests/test-dogfood-entries.sh` fails until every file `git ls-files -- scripts` returns is matched by some `paths/` rule, and #83 rejected a catch-all `scripts/` entry precisely because it would satisfy that leg by construction and the leg could never go red again. So a new script under `scripts/` is a deliberate decision between widening this list and writing the script its own entry, taken by whoever adds it.

**So `paths/00-manual/hooks.md` does not apply here, and following it would be the bug.** "Every failure path exits `0` with nothing injected" is the hook contract; obeying it in `rebuild-tsv.sh` produces a half-written index that nothing reports, which is the exact defect this plugin exists to prevent. Fail loudly instead: a tool that cannot do its job must say so, on stderr, with a non-zero status.

**Three outcomes, never two.** Each of these already distinguishes "nothing to report" from "could not evaluate", and that distinction is load-bearing — an empty report meaning both at once is this repository's own defect class.

| Script | 0 | 1 | 2 |
| --- | --- | --- | --- |
| `jit-dry-run.sh` | every pattern honourable, every index current, every `config.env` line honoured | at least one pattern refused, or a `00-manual/` entry is `STALE` — you did not rebuild | could not evaluate the tree at all. Never a pass. |
| `jit-misses.sh` | findings, **or** the log was read and nothing recurs — the two are distinguished in the text, not the status | — | `SKIPPED`, with a named reason |
| `rebuild-tsv.sh` | the index was written and every row can be honoured | the index was written, and at least one row will be **refused** by the matcher — a `~@macro` it could not expand, written through unexpanded | could not build the index: no `tools/`, `paths/` or `vocabulary/` under `JIT_BASE`, or an index file it could not write |
| `jit-init.sh` | the starter entry was seeded **and** the index rebuilt, so it is live rather than inert | the entry is already there — a copy the user edited is not ours to replace — or the rebuild did not complete | a bad argument, a `--base` that is not a `<project>/.claude/jit-context` path, a symbolic link **at or below `.claude`**, an install carrying no template, or a directory that could not be created |
| `jit-doctor.sh` | nothing inert. Every ADVISORY finding lands here too | a layer holds `*.md` entries and **no** `00-index.tsv`, so the matcher can never load them | a bad argument, a `--base` that is not a directory, or one with no `tools/`, `paths/` or `vocabulary/` under it |
| `jit-match.sh` | every row the hook touched could be evaluated — a match, or cleanly none | the hook also reported something it could not evaluate (a refused row, layer or `config.env` line, or it wrote to stderr), or a candidate match failed index verification — what matched, if anything, still printed | a bad argument, `--base` not a `<project>/.claude/jit-context` path, or no text from either `--text` or stdin |

**`jit-match.sh` answers #205: "which entries does this text call for?", from outside a session.** It shells out to the real `pre-prompt-hook.sh` with `CLAUDE_PROJECT_DIR` pointed at `--base`'s project — the exact pattern `jit-dry-run.sh --prompt` already established for its own sample call — rather than reimplementing the match: the `LC_ALL=C` pin, the Latin-1 fold and the fail-open-loudly behaviour on a malformed byte took several issues to get right, and a second matcher reading the same index drifts the next time only one of them is fixed. The payload it builds carries no `session_id`, so `jit_shown_file()` in `common.sh` returns `""` and every shown-set read/write is a no-op — the shown-set is never touched, and there is no `--session-id` flag to touch it with. `--format json` is hand-built by an `awk` block reusing `jit_json_fields()`/`jit_unescape()` from `common.sh` (the same functions the hooks use to read *their own* payload) rather than a second JSON reader — no `jq`. `--limit N` reports what it dropped, by name, in both formats; a silent top-N would be this repository's own defect class in the tool built to fix it.

**A candidate match is not trusted just because the text splitter found it, and since #219 the splitter itself can no longer be fooled (PR #216, #219).** `.claude/jit-context/` is attacker-controlled input (see `hooks.md`), and until #219 the hook's own join text — a literal `"\n---\n# Vocabulary: "` — could legitimately appear inside one entry's own full-mode body (its raw file content), so the splitter could not always tell a genuine hook-emitted join from the same bytes sitting inside one entry. `pre-prompt-hook.sh` now prepends a manifest naming each block's exact byte length, built entirely from `length()` and never from anything an entry authored — `jit-match.sh` walks the joined text by that count instead of searching it for the separator, which closes the class at the source rather than merely detecting it after the fact. On top of that, every candidate is still checked against the tree's own `00-index.tsv` before it is counted: a real match's `(file, keyword)` pair always exists as a row, by construction, so this can never turn a genuine match into a false refusal — and a candidate that fails is reported once, separately, as `unverifiable`, never silently dropped and never silently trusted. This existence check is kept deliberately even though it is no longer what prevents a fabricated match on the manifest path; it is what `jit-match.sh` still has on the fallback path (a missing or malformed manifest), and it does not fold accents or decide that a match fired.

**The changelog assembler is no longer one of these.** It used to be, at `.github/scripts/assemble_changelog.py`, with this table's `1`/`2` meanings. It is now `.oss/assemble_changelog.py`, vendored from the `oss` plugin, and **its codes are the other way round: `0` ok, `1` skipped, `2` refused.** Do not carry this table across to it — `paths/00-manual/vendored-oss.md` is its subject, and reading a status by number against the wrong contract is the trap.

**A valued flag missing its value is refused, in the argument loop, and every one of these tools does it the same way.** `--base) BASE="${2:-}"; shift 2 ;;` under `set -uo pipefail` with no `-e` is a **hang**, not an error: `shift 2` fails with one positional left, `$1` never advances, and `while [ $# -gt 0 ]` spins. `jit-init.sh --base` and all four of `jit-dry-run.sh`'s flags ran to a `timeout` kill having written zero bytes to either stream (#114), which is the exact inverse of this file's contract — and `jit-dry-run.sh` is the command the hooks' own refusal notice sends authors to, so the caller is usually an agent that then burns its whole budget against no output. The check is `[ $# -ge 2 ] || need_value "$1"` on each arm, because the failing `shift 2` is the mechanism and a wrapper cannot see it. Note what was already right: an **unknown** flag exited 2 loudly the whole time. The quiet path was the *known* one, which is why a sweep here reads every arm rather than the arms someone thought of. `tests/test-arg-flag-values.sh` parses each script's own loop for arms carrying `shift 2`, so a flag added later is covered without anyone remembering to add it — and a flag with no positive control declared beside it is a FAIL, not a skip.

**That suite now enumerates the scripts too, so `while [ $# -gt 0 ]; do` is a shape a new tool has to be in (#188).** Until then the *flags* were read from the source and the *scripts* were a hand-written list, and a new tool was untested there until somebody remembered a line — the same absence, one level up. Every file `git ls-files -- scripts` returns is now classified from its own bytes and gets one of five verdicts, each of which prints a line naming the script:

| Verdict | What it means | Result |
| --- | --- | --- |
| `drive` | the loop is there, with arms carrying `shift 2` | every flag driven |
| `no-flags` | no loop, and no sign of flag parsing anywhere | named PASS |
| `boolean-flags-only` | a loop, but no arm of it reaches for `$2` | named PASS |
| `loop-no-flags` | a loop reaching for `$2`, with no `shift 2` arm to read | **FAIL** |
| `flags-elsewhere` | no loop, but `getopts` / a `shift 2` / a dash case arm | **FAIL** |

There is no skip list, deliberately: a skip list is the hand-written list again one indirection further out. The last two rows are what that costs and what it buys — a tool taking flags in an unfamiliar shape is red rather than quietly untested, and the fix is either the loop shape the other five use or teaching `valued_flags()` to read the new one. The two middle rows exist because "nothing to drive here" and "the parser can no longer read this" are different answers; folding them together would tell whoever writes an all-boolean tool that their parser had rotted.

**The invariant behind every `LC_ALL=C` pin in these five tools, stated once (#195, #196).** An `awk` diverges by locale exactly when it matches a regex against a record that can carry an invalid byte -- a `match:` value, a `keywords:` line, a body under "## Modules", a pattern from `--file`/`--prompt`. Under a UTF-8 locale, one-true-awk aborts the whole program the first time such a match lands on the byte; gawk warns to stderr and keeps going; mawk says nothing and keeps going, which matters most because mawk is the default `awk` on `ubuntu-latest`. Under `LC_ALL=C` none of the three decodes anything, so none of them diverges. A site doing only `index()`, `substr()` and `==` against the record is already safe without the pin -- measured across all nine `awk` sites this repository has, the four sites that were still unpinned when #196 was filed were exactly its four regex sites, and the rest already were. This was re-derived per site four separate times (#116, #163, #169, #177) before it was written down as one rule; if you find an unpinned site that regex-matches a record carrying attacker- or author-controlled bytes, it is this same invariant again, not a new one.

**Pinning the write side is not enough on its own (#195).** A locale abort is loud on exactly one engine (one-true-awk) and silent on the one CI actually runs by default (mawk). Pinning the divergent sites removes the abort everywhere, which is correct -- but only once whatever reads the result afterwards can still tell a bad byte from a clean one. `rebuild-tsv.sh`'s own `report_bad_bytes()` (below) is that downstream check, and it existed before this pin; what #195 fixed alongside the pin was the append that skipped it -- `awk ... >> "$tsv"` with no exit-status check, so an awk that died for *any* reason, byte or otherwise, left a partial file and the run still reported success. Check the exit status of anything that writes to an index, not only the awk that might abort on this specific invariant.

**`jit-dry-run.sh`'s two pattern probes run `LC_ALL=C`, because the hooks do.** A verdict reached in another locale is a verdict about a different matcher: unpinned, the structural probe aborted with `towc: multibyte conversion failure` on any pattern carrying a non-UTF-8 byte — printed into the middle of the report, with an empty verdict captured behind it — and the engine probe called a row fatal that the hook accepts (#116). Its third verdict line is split accordingly: `FATAL — nothing refuses this row first, so it alone silences every rule in its index` is now said **only** when `jit_bad_pattern()` passed the row, since a row the guard refuses never reaches `match()` and takes nothing with it. Saying it of every rejected row was true of one shape and false of the common one, and an overstated warning is discounted on the day it is exact.

**`jit-dry-run.sh` has five verdicts per row: `ok`, `REFUSED`, `SKIPPED`, `STALE` — and two that never move the exit code, `WARN` and `ADVISORY`.** A `SKIPPED` row is one the tool could not evaluate — the row reader exited non-zero over that index, or a hook wrote to stderr on the sample call — and it exits `1` like a refusal. It exists because `2>/dev/null` on the row-bytes `awk` turned a **fatal** into an empty result set, which reads as a clean index, and `awk` aborts *at* the record, so every row below it went unreported too: a bad-UTF-8 row was named when it was alone and vanished when a row that killed the reader came first, under `0 refused` and exit `0` (#98). If you add a check here, the question to answer first is which of those a failure to evaluate produces.

A `WARN` or `ADVISORY` row in `jit-dry-run.sh` never moves the exit code, and neither does `rebuild-tsv.sh`'s **advisory** ambiguous-keyword tally. Those entries are indexed and fire correctly; nothing about them is refused, and failing on them would make the documented default tree exit non-zero and teach every author to ignore the status. If you add a check, decide which of those it is before you write it.

`ADVISORY` is the newest of them and the reason is worth having in one place: a tools row that can refuse a call — `block` in the mode column, or a non-empty `require` or `forbid` — and matches on a bare, non-`~` substring is tested against the command **truncated** at the first `;`, `&`, `|`, `"` or ` --`, so a chained command walks straight past it (#136). The truncation is `pre-tool-hook.sh`'s `cmd = full_command` strip, under the comment that opens `Strip to command words`, and it is correct; what was wrong is that the row read as enforced and nothing said otherwise. Two consequences to keep if you touch it: the predicate is the hook's own `can_refuse`, not just `block`, or two thirds of the shape is silent; and it is exit `0`, because CI consumes this code (#47) and failing every project that ever wrote a bare `block` rule is a breaking change nobody filed.

`ADVISORY` is a verdict class rather than one check, and #147 is the second row wearing it: an entry whose `inject:` value is neither `full` nor `summary` silently took the project default. Reuse the word rather than inventing a sixth verdict — the row is `<verdict, 9 wide>%-18s %-30s <free text>`, and a new verdict word is exactly how #134 broke that. The reason string for it existed since #1 and could reach stdout on **neither** default: it travelled only through the whole-body budget list, which a row joins only when its *effective* mode is `full`, so the `full` default never prints that list and the `summary` default resolves the mistyped row to `summary`. Exit-code-neutral for the same reason as the row above it — the entry is indexed, the rule fires, the default did apply. The value it prints is tree text and goes through `jit_report_name()` like every other column here.

The second advisory report — there are six now, and this is the one to read before you add a seventh, because it is the one where the answer was not obvious. A `keywords:` term matching `JIT_CONTEXT_KEYWORD_BLACKLIST` is skipped at index time, so the entry never fires on that word; until #95 it was skipped with a bare `continue` and nothing anywhere said so. It is now **named, with its entry file, and still exit `0`** — because skipping a generic word is the documented behaviour of the field rather than an author's mistake, because no row was written and so nothing is *refused* in the sense `1` means, and because the pattern is project-configurable: a project that widens it would exit non-zero on every rebuild forever. What was missing was the sentence, not the status.

The third is `Entries on disk with no row in the index` (#44), and it is advisory for the same two reasons: no row was written, so nothing is refused in the sense `1` means, and a layer directory may legitimately hold a note that was never meant to be an entry. It fires on the four silent `continue`s in the indexer — a `paths/` entry with no `match:`, a `vocabulary/` entry with no `keywords:`, a `tools/` entry missing `tool:` or `match:`, and an entry whose every keyword the blacklist dropped. Each is **recorded at the point of the drop**, never inferred afterwards by diffing the `.md` glob against the index: the indexer knows *why*, and a diff would have to guess between "no `match:`" and "every keyword was blacklisted", which are two different fixes. The number it prints is a count of **files**, and the line says so — bytes and tokens are the budget report's business, one section down.

A fourth, `Entries whose keywords are ALL generic` (#232), is advisory for a reason none of the three above share: a row WAS written for every one of these entries, and nothing about the row is wrong — the fallback clears the "generic" verdict back to empty on it before the write, which is the same empty column an index built before the generic-verdict feature landed, or a keyword absent from the wordlist, already produces. So the entries it names are not a defect to fix; they are entries relying on a safety net rather than owning a specific keyword of their own, and the report exists so an author can see that and choose to add one, not because the tree is wrong as it stands.

**Every report here may print a file name; none of them may print an arbitrary one.** `.claude/jit-context/` arrives with the clone, so an entry file name and a layer directory name are attacker-chosen text — and the same channel has now been found four times: in `pre-tool-hook.sh` (#35), across six reports in `rebuild-tsv.sh` (#113, #232), and in every report `jit-dry-run.sh` prints, both the per-row lint and the sample call (#124). One entry carrying a blacklisted keyword was the whole `rebuild-tsv.sh` trigger; no rule had to match and no hook had to fire, and `CLAUDE.md` tells the agent to run that tool after every frontmatter edit, so the output lands in a model's tool result by instruction. `common.sh` had already argued this for the hooks and answered it with `jit_row_id()` — a refused row named by *position*, never by the text of its file-name column, because 250 bytes of English pass a bare-name check intact.

`jit_report_name()` in `common.sh` answers it differently for these tools, and the difference is the point. A hook runs with no author present; these are run **by** the author, and the file name is the entire actionable content of most of their reports — `vocabulary/00-manual row 7` sends that person to count lines in a generated file. So the name is kept when it *is* a name — `[A-Za-z0-9]` then `[A-Za-z0-9._-]*`, at most 64 bytes — and replaced by `<withheld: not a plain name>` otherwise. The set is chosen for one property: **no space.** An instruction is prose and prose is words with spaces between them; no length cap separates the two, since `Run rm -rf ~` is twelve bytes. The cost is accepted — an entry honestly called `my rule.md` loses its name in these reports, and the reader `ls` the layer printed beside the placeholder.

**One policy, in one place, because a second answer to this question is itself the defect.** It lives in `common.sh` and that is now the only bash definition — `rebuild-tsv.sh` carried the copy #113 landed until #131 deleted it, and it sources `common.sh`, so every call site there is the one answer. The second implementation that *cannot* go is the awk one: three of `rebuild-tsv.sh`'s reports are built inside `awk`, `awk` cannot source a bash file, and `JIT_AWK_REPORT_NAME` restates the same character set in another language. `tests/test-dry-run-names.sh` drives that pair against each other on every boundary of the set — it is the drift that is still possible, and nothing pinned it before #131.

**Two columns carry a KEYWORD rather than a name, and `jit_report_name()` is the wrong guard for them** (#126). Its set is chosen for having *no space*, and `vat rate` is a legitimate keyword — normalised to exactly that, spaces included, by the code that writes the index. A guard that withheld every multi-word term would pass every negative test and make the ambiguity report useless in its ordinary case. So `jit_report_keyword()` admits the space and bounds the term instead: `^[a-z0-9][a-z0-9 -]*$` — the bytes the keyword normaliser actually emits, so anything else means the term did not come from this run — at most **40 bytes** and at most **4 words**, and `<withheld: not a plain keyword>` otherwise. The entry *files* print either way, so a withheld term is still something an author can grep for.

Be honest about what that buys: no bound that admits `vat rate` can refuse all imperative English — `delete all ssh keys` is four words and 19 bytes. What it removes is the *unbounded* channel, which is the paragraph, the forged line and the control character. The dropped-keyword report is guarded too, and the argument for leaving it alone was **wrong**: `rebuild-tsv.sh` claimed its `$kw` was safe because `VOCAB_KEYWORD_BLACKLIST` is "anchored `^(...)$` on single words, so a keyword that reaches that report is one of a closed set". That set is not closed — the blacklist is project-configurable and `config.env` arrives with the repository, which is the same file that paragraph says would make a widened project exit non-zero forever.

The half that was never a judgement call: **a newline in a name forged a whole report line**, in the tool's own voice. The same character set closes it. Two things decide where a newline can even arrive: an index row read with `IFS=$'\t' read -r` cannot carry one, but a name read from a **glob over the filesystem** can — that is why `jit-dry-run.sh`'s `STALE` report and its whole-body budget were the two forging sites, and a layer *directory* name is in that class at every site. If you add a report, route its names through `jit_report_name()` (bash) or `JIT_AWK_REPORT_NAME` (awk, and invoke that `awk` `LC_ALL=C` — the set is a *byte* range, and under a UTF-8 locale both bash's `[A-Za-z0-9]` and awk's admit accented letters; measured, `café.md` passes unpinned and is withheld pinned). Withholding is a **report** decision only: the row is still indexed under the real name, the rule still fires, and the linter still lints it.

**A withheld name must not cost the reader the row.** `jit-dry-run.sh` keeps every refused row identifiable without printing the name: a `REFUSED`/`WARN` pattern row still prints its pattern verbatim on its own `untrusted>` line, and `check_entry_file()` — the one report whose whole class is unprintable, since a name carrying a separator is never a plain name either — closes with the position, worded exactly as `jit_row_id()` words it for the hooks. A fix that withheld the name and said nothing else would have replaced a disclosure with a dead end.

One line here prints a whole path rather than a name, and it needed a second fix: `truncate_index()`'s `FATAL`. Its `: > "$tsv" 2>/dev/null` applied the redirections **left to right**, so the failing one was set up while stderr was still the terminal — bash printed its own diagnostic carrying the absolute path, and the `2>/dev/null` that followed silenced nothing. A clone reaches that branch on purpose by shipping a *directory* named `00-index.tsv`. The redirection is now `: 2>/dev/null > "$tsv"`, and the reason bash would have given is replaced by the one case that is constructible. The `FATAL` then names `JIT_BASE` on its own line: the display string is `dimension/layer/leaf`, so the absolute path went with the withheld component, and the *ordinary* failure here — a read-only tree, a full disk — is the one where the reader needs a path they can act on.

**A check here has to agree with the hooks, because the hooks send people here.** The refusal notice they inject ends with `bash scripts/jit-dry-run.sh --base <tree>`, so a class the hooks refuse and this tool reports `ok` for makes that advice false — this repository's own defect class, in the tool written to report it. The byte checks (`#77`, `#78`) are read off the same `common.sh` functions the hooks use rather than a second copy in bash. Two traps came with them: `read -r` in the row loops truncates at a NUL, so that pass is one `awk` per index file rather than a bash loop; and that `awk` must be invoked `LC_ALL=C`, because the byte range it builds is a decode failure in a UTF-8 locale — unpinned, one-true-awk aborted the whole program on the first row of a tree carrying the byte the check exists to find.

`rebuild-tsv.sh`'s codes were only added in #47 — until then it reported a refused macro on stderr and exited `0`, so CI could not tell a clean rebuild from one that indexed a pattern the hook will refuse. Two things about them are worth knowing before you change them:

- **`1` is not a general lint tally.** `jit_expand_match()` returns 0 for every value that is not a macro, so the only way to reach `1` is a `~@macro` an author wrote and got wrong. That is why there is no `--strict` flag: the `&&` chain that stops belongs to the person who just wrote the dead rule, and a flag only CI passes would hand that person back the exit `0` that was the bug.
- **`2` cannot be `[ -d "$JIT_BASE" ]`.** It used to be unusable for a reason that no longer holds — `common.sh` `mkdir -p`ed `$JIT_BASE/.discovery/logs` unconditionally when it was sourced, so the base directory existed by the time this script ran even in a project with no entry tree at all. Since #51 that `mkdir` is gated on the tree already existing, so the test would now answer honestly. It is still the wrong test: a `.claude/jit-context/` with no `tools/`, `paths/` or `vocabulary/` under it is a tree this script cannot build an index for, and `[ -d "$JIT_BASE" ]` would call it fine. The guard asks whether any **dimension** directory is there.

**`rebuild-tsv.sh` is the only writer of `00-index.tsv`.** The markdown is the source; the TSV is what the hooks read, and nothing else may write it — `tools/00-manual/no-hand-editing-the-index.md` blocks an `Edit`/`Write`, and `no-shell-writes-to-the-index.md` blocks the three shell write forms anyone actually types (#92) — neither is a sandbox, and the second says so in its own body. It also expands the `~@invocation` macros into real EREs, so a macro it does not know is refused, named, and written through unexpanded, which makes the hook refuse that row too rather than silently match nothing.

**`jit-init.sh` resolves `--base` before it writes, and refuses only from `.claude` down.** A link *above* `.claude` — `/tmp` on a Mac, a bind mount in a container — is followed and the receipt names the physical location it landed at, because pointing `--base` anywhere is the tool's job and the hooks do not care how the project directory is spelled. A link *at or below* `.claude` is still refused, because the hooks refuse to read an entry through one: seeding past it writes a rule that can never fire, which resolution cannot repair. Refusing the ancestors too was the other candidate for #99 and was rejected — it breaks ordinary Macs and containers to fix a receipt. There is no `realpath` on macOS, so resolution is `cd -P` on the deepest existing ancestor plus a textual fold of the components below it, which do not exist yet and therefore cannot hold a link.

**`jit-init.sh` does not source `common.sh` either, and for the same reason.** `common.sh` resolves `JIT_BASE` from `$CLAUDE_PROJECT_DIR` and `mkdir -p`s a log directory under it at load — since #51 only where a tree already exists, which is exactly the case a second project on the machine is in; the tree `jit-init.sh` seeds is the one `--base` names, which need not be that project. A tool that creates a directory in a third place on the way to creating one where you asked is a tool whose receipt lies. It writes exactly one entry, copied from `templates/jit-context/`, and **refuses rather than overwrites** — the copy in the project belongs to whoever edited it (#81).

**`jit-misses.sh` does not source `common.sh`, on purpose.** `common.sh` `mkdir -p`s the log directory at load, and a reporting tool that creates the thing it reports is a tool whose own output cannot be trusted. Since #51 that `mkdir` is gated on `.claude/jit-context/` already existing, so it no longer materialises a tree in a project that has none — but it still creates `.discovery/logs/` in every project that has one, which is every project this tool is pointed at. The reason is unchanged; only the size of what it would create is smaller. Do not "fix" the missing `source` line. `rebuild-tsv.sh` and `jit-dry-run.sh` do source it — and a change you make *inside* `common.sh` is governed by `hooks.md`, not by this file.

**In `jit-misses.sh`, stdout is the report and every refusal goes to stderr.** The rule at the top of this file — say so on stderr, with a non-zero status — had its second half right here and its first half wrong: the status was `2` and the text went to stdout (#125). It matters because a caller doing `bash scripts/jit-misses.sh > misses.txt` captured `jit-misses: SKIPPED -- not readable` into the findings file, under no heading, where it reads as a finding. A refusal that reads as a finding is this repository's own defect class, arriving through the stream rather than through the status.

Three of its refusals are built inside the `awk` `END` block, and `print` there goes to stdout. `print ... > "/dev/stderr"` was rejected: all three `awk`s this repo cares about special-case that name, but Git Bash is a CI leg nobody here can observe, and an `awk` that opened it as a real file would abort on a platform where it is not there — trading a stream bug for a tool that says nothing at all. A temp file was rejected too, because `--help` promises this script writes nothing and creates nothing. So the `awk` run is **buffered** and the stream is chosen from its exit code: `2` to stderr, anything else keeps stdout. `$( )` is safe for that specific subject — every byte of `hooks.log` was written through bash variables, which cannot hold a NUL. `--help` is not a refusal and keeps stdout.

**`jit-misses.sh` reads a file the hooks wrote, so its `awk` is pinned to `LC_ALL=C` too.** The hooks truncate the prompt copy at 80 **bytes**, so an ordinary CJK or heavily accented prompt leaves a half-finished UTF-8 sequence at the end of a log line — no attacker, no malformed input. Reading that back aborted this tool with `illegal byte sequence` under one-true-awk and made gawk warn (#68, one hop downstream from the hooks). Failing loudly is this file's contract, and it still holds — a log this tool cannot read gets a named `SKIPPED` and exit 2. Choking on bytes the plugin wrote itself is not that. The fold table here is the byte-identical copy of `common.sh`'s, `index()`/`substr()` with no decode and both cases listed, so `C` costs it nothing.

**No new runtime dependencies, same as the hooks.** `awk` and `perl` only. No `jq`, no Python, no Node. These ship inside the plugin and run on Linux, macOS and Windows (Git Bash); `find -delete` is not POSIX and GNU-only flags are not available.

**`match` is an awk ERE.** `\s` `\d` `\w` compile to the bare letter and match nothing; `\b` is a backspace character. `rebuild-tsv.sh` writes the pattern and `jit-dry-run.sh` lints it, so both ends of that guard live here.

**A suite that drives `rebuild-tsv.sh` over a deliberately broken fixture must not run under `set -e`.** `test-invocation-macro.sh` and `test-frontmatter-quotes.sh` each build a tree containing a macro the writer refuses, on purpose — since #47 that rebuild exits `1`, and `set -e` would abort the suite at the fixture it exists to construct. They use `set -uo pipefail` for that reason; adding the `-e` most other suites carry is the tidy-up that breaks them.

**Write the test first and watch it fail.** A test written after the fix asserts what the code happens to do. `paths/00-manual/tests.md` fires when you open the suite and carries what makes an assertion here non-vacuous.
