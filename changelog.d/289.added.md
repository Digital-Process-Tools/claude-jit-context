Codex is a supported host. `.codex-plugin/plugin.json`, `hooks/hooks.codex.json` and a self-referential `.agents/plugins/marketplace.json` bind the same `scripts/*.sh` Claude Code already runs, so no hook code was written for it (#289, closing the build half of #252).

The `codex` row in `scripts/host.sh` moves to `OBSERVED` on evidence rather than on another plugin's: #288 ran a probe plugin against a real `codex-cli 0.150.1` and watched `PreToolUse` fire, carry `tool_name` and `tool_input.command` under those exact names, and stop a real command with `{"decision":"block"}`. `permissionDecision: deny` blocks identically; `additionalContext` injects and lets the call through. Codex takes the same envelope Claude Code does, in both directions, so there is no per-host translation to write.

Two findings changed the design rather than confirming it:

- **The old `codex` signature could never have fired.** It claimed `CODEX_SESSION_ID,CODEX_THREAD_ID`. All 54 variables of a real Codex hook environment were captured and no `CODEX_` variable was among them. Those two detection fixtures are removed rather than inverted — there is nothing left to detect Codex by — and `jit_host_detect()` is now documented as best-effort and non-load-bearing. What makes that safe is asserted rather than assumed: the two rows carry identical contracts, and the suite fails if they ever diverge.
- **Detection answers the wrong host under exactly the conditions this plugin runs in.** A Codex hook launched from inside a Claude Code shell inherits `CLAUDE_CODE_ENTRYPOINT` and `CLAUDE_CODE_SESSION_ID` from its parent, so it detects as `claude-code`. That is now a test fixture, because it is the failure that actually happens.

`hook-not-trusted` joins the refusal states. Codex keys a `trusted_hash` per hook, and a hook with no entry is **silently skipped** — no warning, no non-zero exit, no transcript line, the tool call simply proceeds. It is neither `unsupported` (the host cannot block) nor `refusal-not-established` (nobody checked): the host can, we asked, and it declined to run us. `jit_host_refusal_honoured()` is the single place that decides, so no caller can read any of the three as permission to emit a block that will be ignored.

`.codex-plugin/plugin.json` is a fifth version site and is listed in `.oss.json` — the two manifests must move together at release time, and the suite fails if they drift.

Gemini CLI is untouched and still `UNKNOWN`. #252 is explicit that Gemini, not Codex, is the design's real test, and nothing observed here speaks to it.
