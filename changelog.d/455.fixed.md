- **The `claude plugin validate --strict` reserved-name exception in the release smoke test is removed now that the plugin is renamed** (#455, carried forward from the v0.13.0 gate-3 security audit round 1). `_only_reserved_name_error()` in `.github/scripts/smoke_release_tree.py` (#445/#448) let exactly one validate error through as a warning when the validator's own output named the plugin a reserved name -- CLI 2.1.287 rejected the `claude-` prefix this repository carried at the time. #452 renamed the plugin away from that prefix, so `claude plugin validate --strict` no longer reports that error for this tree, and the carve-out was dead code going forward. It also had an independent parsing gap: a second real error block whose own heading did not match the regex it expected (e.g. a per-file heading like `Found 1 error in hooks.json:`) was never counted, so the function could still return true and let a genuine second error through.
  Removing the whole exception settles both at once: a future `claude plugin validate --strict` error of any kind, reserved-name shaped or not, recognized heading or not, now fails the smoke test outright rather than carrying forward a carve-out whose only remaining effect would be to mask some unrelated error.
