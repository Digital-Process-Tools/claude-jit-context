# data/generic-words/ -- the generic-word list, split into chunks

The ordinary-word dictionary `rebuild-tsv.sh` and `jit-misses.sh` both read (#232, #386):
one lowercase token per line, blank lines and `#` comments ignored by the reader that cares
(`jit-misses.sh`; `rebuild-tsv.sh`'s reader loads every line into its hash, including the
comments above, and a comment line can never match a normalised single-word keyword anyway).

**Why a directory of chunks instead of one file (#437):** the Anthropic plugin directory
holds any non-image file of 256 KiB or more. The single `data/generic-words.txt` this
replaced was 1,027,699 bytes, 103,843 lines -- about 4x that limit on its own. Splitting it
is NOT a content change: concatenating every `chunk-NN.txt` here, in filename order, byte for
byte reproduces the original file exactly (`cat chunk-*.txt | cmp - <old file>` was run clean
before the old file was removed). Nothing was reordered, deduplicated or re-encoded.

Both readers load every chunk in this directory (sorted by name) as if it were one file; see
each script's own comment at its generic-word resolution for how. A caller who wants a single
custom wordlist instead -- `JIT_CONTEXT_GENERIC_WORDS`, `DYNAMIC_RULES_GENERIC_WORDS`, or
`jit-misses.sh --generic-words PATH` -- still points at one plain file, exactly as before;
only the SHIPPED default moved to a directory. A configured path that names a directory is
read the same chunked way as the shipped default.

PROVENANCE is unchanged from the file this replaces -- SCOWL (English) + Dicollecte (French),
hand-assembled for #251 -- see the top of `chunk-00.txt` for the full note, carried over
verbatim from the original file's header.

#459: two network-tool command names were removed from `chunk-01.txt` (lines 2880 and
20142 respectively, before removal). Both are ordinary dictionary words in isolation, but
each is also the name of a download tool, and the Anthropic plugin directory's validator
reads a bundled word list for exactly those names when deciding whether a plugin folder
"can send data off the machine" -- it held on one of the two appearing in `chunk-01.txt`.
Their other-sense inflections (e.g. the hair-curl senses of one of the two) were left in
place; only the two exact words that are also a download-tool name were dropped. A handful
of other download/transfer tool names were checked and were never present in any chunk.

#461: the validator then held on a third network-tool name, so three more words that are
also the name of a network command or protocol were removed (one from `chunk-01.txt`, two
from `chunk-02.txt`). A keyword equal to one of them is now classified `specific` rather than
`generic` by `rebuild-tsv.sh`, which is the safer side: an entry keyed on it fires rather than
being set aside.

#461, last pass: the hold moved one word per scan, so every word that is also the name of a
network, mail, chat or download client, or of a package manager, was removed in one sweep
(nineteen more across the chunks). Same consequence as above: such a keyword now reads as
`specific`.

Regenerating after an edit to the word list: edit the content (add/remove lines) in any chunk
or across chunks, keep each chunk comfortably under 256 KiB, then `bash scripts/rebuild-tsv.sh`
as usual -- nothing here is itself generated by a script, unlike `00-index.tsv`.
