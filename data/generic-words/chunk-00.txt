# Generic-word list consulted by rebuild-tsv.sh (#232) to classify a vocabulary
# keyword as an ordinary word rather than a project-specific identifier. One
# lowercase token per line; blank lines and lines starting with "#" are ignored.
# Consulted only at rebuild time -- never at prompt time -- so this file changes
# nothing about the runtime dependency list scripts/*-hook.sh is held to.
#
# PROVENANCE (#251, replacing the #232 hand-curated stand-in shipped in PR #250).
#
# English: SCOWL (Spell Checking Oriented Word Lists), size 35, "words" category
# only (proper nouns, abbreviations, contractions and the "upper" category are
# excluded so a project token is never classed as ordinary).
#   Source:  https://sourceforge.net/projects/wordlist/files/latest/download
#   Version: 2020.12.07 (SCOWL zip's own VERSION file), fetched 2026-09-01.
#   License: SCOWL's own Copyright file -- "Permission to use, copy, modify,
#            distribute and sell these word lists ... for any purpose is hereby
#            granted without fee, provided that the above copyright notice
#            appears in all copies" -- a permissive, BSD-compatible grant, by
#            Kevin Atkinson, 2000-2018. Component sources folded into SCOWL's
#            size-35 tier (Moby Words II, Brian Kelk's UK wordlist, 12Dicts) are
#            each separately placed in the public domain per that same file.
#   Dialects combined at levels 10/20/35 (SCOWL's own README: "the 'english'
#   spelling category should be used as well as one of 'american', 'british', …"
#   -- here all of them, for coverage, since this consumer only asks membership
#   and never spelling-correctness): american, australian, british, british_z,
#   canadian, english, variant_1, variant_2, variant_3.
#   41218 words, 384 KB, from final/{dialect}-words.{10,20,35} with a trailing
#   CRLF stripped and non-lowercase-alpha lines (proper-name-only artifacts,
#   Unicode outliers) dropped.
#
# French: Dicollecte/Grammalecte's fr.dic stems, MPL 2.0, mirrored through
# LibreOffice's own dictionaries repository (dicollecte.org itself now resolves
# to an unrelated parked domain and was not used).
#   Source:  https://raw.githubusercontent.com/LibreOffice/dictionaries/master/fr_FR/dictionaries/fr.dic
#   Version: dictionnaires orthographiques français 7.7 (fr_FR/dictionaries/README_dict_fr.txt)
#   License: Mozilla Public License 2.0 -- https://www.mozilla.org/MPL/2.0/
#   Hunspell stems only (the flags after "/" on each .dic line are affix rules,
#   not part of the word; #232's own research: "the stems are likely sufficient,
#   since matching operates on single normalised tokens"). Capitalised entries
#   (proper nouns, sentence-initial forms) and anything carrying a digit,
#   apostrophe or space are dropped, keeping only pure-lowercase stems.
#   ASCII-folded through the SAME table pre-prompt-hook.sh's / rebuild-tsv.sh's
#   own jit_fold_latin1() uses (JIT_AWK_FOLD in scripts/common.sh) -- NOT the
#   raw accented spelling. This is load-bearing: the classifier folds the
#   KEYWORD before comparing it against this file, but never folds this file,
#   so an accented row can never match a folded keyword. #232 named three rows
#   in the PR #250 stand-in that were dead for exactly this reason (meme,
#   detail, equipe, stored accented); this export is folded up front so the
#   same class of row is never introduced again.
#   66690 words, 676 KB, deduplicated after folding (folding can merge two
#   distinct accented spellings onto one ASCII row).
#
# Combined: 103776 unique words (4132 already shared between the two source
# lists after folding), ~1.0 MB total -- up from the 229-line, 4 KB stand-in
# this file replaces. That is this change's whole repo-size cost; nothing
# under scripts/ changed, and GENERIC_WORDS_FILE already pointed at this path.
#
# Re-measured against #232's own question (this repo's own corpus, 22 keyword
# rows across 3 vocabulary entries): zero entries are reachable only through
# generic keywords, unchanged from the 196-word stand-in. Every keyword in this
# repo's own vocabulary entries is either multi-word ("invocation macro",
# "state file") -- which normalises to a space-joined string that can never
# equal a one-word wordlist line -- or a single word absent from both source
# lists (jit-context, handoff, statusline, oss-watch, ...). That is a fact
# about this repo's own vocabulary keywords, not a property of the classifier
# or this list -- a bigger list can still only move the count upward on a
# corpus that has a single ordinary word as an entry's sole keyword.
#
