Self-review on #403 (oss:auditor spawn) found that `assert_single_valid_json()` -- the
helper `tests/test-uncaptured-awk-crash-403.sh` itself calls "the discriminating check"
(it counts DECODED json objects, the thing that caught the #397 self-review's double-print
class) -- silently no-ops on a host without `python3`: it prints a `SKIP` line and returns
without touching `$PASS`/`$FAIL`. Because the suite's overall exit is `[ "$FAIL" -eq 0 ]`,
that means a host missing `python3` reports a clean pass while its own stated
discriminating assertion never ran, with nothing in the exit code or tally distinguishing
that from a genuine pass.

This is not new to #403: the exact same helper, byte-for-byte, already exists unchanged in
`tests/test-awk-crash-397.sh` (the file #403's own suite says it copies the discipline
from) and in `tests/test-jit-match.sh`. So this is a pre-existing shape in this codebase's
own test-authoring convention, not something #403 introduced -- the auditor's own framing:
"already true elsewhere," grounds to treat it as informational on this PR rather than a
fresh defect, but worth a fix somewhere upstream of any one PR.

What was NOT chased: whether `python3` (not `python`) is actually present on the
`windows-latest` runner `.github/workflows/tests.yml`'s `hooks` matrix job uses (4 Windows
shards, `defaults.run.shell: bash`). If it is not, this degrade is live on every CI run
today, on every suite that uses this helper, and has been since #397 shipped it.

Candidate shapes for whoever curates this: (a) count a python3-less skip toward a separate
tally `run-all.sh` already has room for (the same `SKIPPED` bucket the suite's own two
preconditions use, rather than a silent per-assertion no-op), or (b) a repo-wide rule that
`assert_*` helpers used as "the discriminating check" for a suite's whole stated purpose
must not be satisfiable by an environment gap the suite's own doc claims it does not have
(the file's OWN precondition checks for SIGSEGV-shimming and chmod-555-unwritability
already do this correctly -- loud, whole-suite `exit 2` -- so the shape to copy already
lives in the same file next to the shape that does not).
