Same defect class as #424 (a CLAUDE_PROJECT_DIR-derived path passed to awk via -v,
silently escape-decoded), found by Explore's self-review of that PR in
scripts/rebuild-tsv.sh, in two more places, neither touched by #424:

1. The ambiguous-vocabulary-keyword collision report builds `layerdir` (a glob under
   `VOCAB_BASE="$JIT_BASE/vocabulary"`, itself CLAUDE_PROJECT_DIR-relative) and hands
   it to awk via `-v layerdir=...`. The awk function `bytesof()` then does
   `getline line < (layerdir "/" $2)` using the -v-decoded (potentially mangled) path.
   On a backslash-bearing CLAUDE_PROJECT_DIR, every open fails and every entry in that
   layer is reported as "unmeasured" instead of its real byte count -- a reporting-only
   break in a tool a maintainer runs by hand, not a hook that runs in a stranger's
   session.

2. The generic-word classifier pass builds `-v wf="$GENERIC_WORDS_FILE"` (also
   CLAUDE_PROJECT_DIR-relative or override-derived) and reads it with
   `getline w < wf` inside the awk BEGIN block. A mangled `wf` leaves the `seen[]`
   lookup table empty, so every keyword silently classifies as non-generic --
   this still returns one verdict per keyword (so it passes rebuild-tsv.sh's own
   count-mismatch guard undetected), just the wrong verdict for all of them.

Fix shape: same as jit-misses.sh's own fragment (#424.jit-misses-generic-words-v-escape.md)
-- route layerdir/wf through ENVIRON, matching the technique #424 already used for
JIT_BASE/tools_base/vocab_base.

Not fixed as part of #424 itself: a third file, a maintainer-only tool (not a
per-session hook), and each needs its own fixture to pin (a real byte-count
divergence for #1, a keyword-classification divergence for #2).

Source: Explore's self-review of PR fixing #423/#424, scripts/rebuild-tsv.sh (grepped
around VOCAB_BASE/layerdir/bytesof and GENERIC_WORDS_FILE/wf -- not cited by line
number, see this repo's own line-citation rule).
