Observed (release audit round 2 for v0.14.0, token jitrel-f53a3c70, finding B2, row misreports):
`tests/test-release-branch-461.sh` passes the check step on
`[ "$CHECK_RC" -eq 0 ] || [ -z "$UNEXPECTED" ]`. When check_release_tree.py crashes, its
traceback has no `^FAIL ` line, so UNEXPECTED is empty and the suite prints
"PASS: check_release_tree.py reports no offender in the built tree". The auditor ran that
condition with CHECK_RC=1 and a traceback as output and got the PASS line. CI is covered
(the workflow's own check step reads the exit code); a local run-all.sh is not.
test-release-branch-437.sh has the same shape from before this range.

Settles it: a non-zero exit with no FAIL lines is a failure, not a pass.
