Observed (release audit round 2 for v0.14.0, token jitrel-f53a3c70, finding B1, row misreports):
`.github/workflows/release-branch.yml`'s step "Equivalence test the compiled scripts (#461)"
runs `tests/test-release-branch-461.sh`, which builds `--ref HEAD` of the checkout. The
workflow itself builds and publishes `$SOURCE_REF`. On a tag push they are the same commit.
On `workflow_dispatch` with `ref=<an older tag or sha>` (the input's own description invites
that), the checkout is the dispatching branch, so the equivalence step goes green on main's
tree while a different tree is published. check_release_tree.py and the smoke test do run on
the built tree; only the source-vs-compiled equivalence is missing on that route.

Settles it: pass the built ref (or the built tree's path) into the test instead of HEAD.
Cost so far: nothing shipped wrong; found by reading, not by a failure.
